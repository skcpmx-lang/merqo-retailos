## 4. Scanner Implementation
Enhanced src/renderer/hooks/useBarcodeScanner.ts:

- Supports USB HID, Bluetooth HID, Wireless HID all as keyboard emulation, no paid SDK, offline, no cloud.
- Scanner input buffer: bufferRef, lastCharTimeRef, firstCharTimeRef, timeoutRef, isScannerBurstRef.
- Detects rapid sequences: inter-char < charThresholdMs (default 50ms), total <500ms, length >=6 → scanner.
- Configurable suffix: ScannerSuffix 'Enter' | 'Tab' | 'None'. Most scanners send Enter, some Tab. If suffix None, timeout-based auto-scan.
- Supports Enter and Tab suffix via handleKeyDown, prevents default, calls handleScan.
- Prefix/suffix handling: optional prefix stripped via normalizeBarcode(prefix).
- Clear stale buffer safely: setTimeout scanTimeoutMs (default 150ms) clears buffer if inactive, prevents memory growth, avoids stale buffer leaking.
- Prevent leaking: if scanner burst detected and not in regular input, preventDefault; also if in regular input (not barcode) and fast, preventDefault to avoid corrupting field. Preserves normal keyboard typing: slow typing >charThresholdMs treated as human, not scanner, buffer cleared if in regular input.
- Handle scan while POS focused: global window keydown listener works even if focus elsewhere, routes to POS cart regardless of focus, except when in modal handling barcode.
- Handle repeated scans: buffer cleared after each scan, immediate next scan allowed, duplicate scan logic in POSScreen increments quantity.

New pure utilities for testing: isScannerTiming(timestamps, charThresholdMs, maxTotalMs) → {isScanner, avgInterval, totalTime}, normalizeBarcode(raw, prefix).

Documented why timing detection: Focus-based alone not robust because scanner may type while focus elsewhere; timing allows global capture without requiring focus, while preserving normal typing via threshold 50ms (scanner 5-15ms, fast human 80ms+).

Configurable via ScannerConfig from main process: enabled, minLength, maxLength, suffix, charThresholdMs, scanTimeoutMs, prefix, testMode, updatedAt. Persisted in system_settings key hardware_scanner_config via PrinterService.

## 5. Scanner Input Handling
- Captures rapid key sequences via keydown listener, buffers printable single chars.
- Detects configurable suffix Enter/Tab/None.
- Handles scanner prefixes/suffixes where practical via normalizeBarcode.
- Clears stale buffer after scanTimeoutMs, safe reset.
- Prevents barcode characters leaking into unrelated fields when scanner mode active via preventDefault when isScannerBurstRef true and not in input or in regular input fast.
- Preserves normal keyboard typing: slow typing flagged isScannerBurstRef false, buffer cleared if in regular input.
- Handles barcode scan while POS focused via global listener, even if focus not in barcode input.
- Handles repeated scans via clearBuffer after each scan.

Manual barcode entry preserved via useBarcodeInput hook: Input field with data-barcode-input attribute, Enter triggers onScan, value cleared.

POS integration: globalScanner hook in POSScreen uses scannerConfig from main process (minLength, charThresholdMs, scanTimeoutMs, suffix, prefix), calls handleBarcodeScan which uses existing product lookup POS_PRODUCT_BY_BARCODE.

## 6. Barcode Workflow
Scan barcode → lookup product → product found → add to POS cart → repeated same barcode increments quantity → conversion applied when needed → price/unit rules preserved → stock validation preserved.

Implementation:
- POSScreen handleBarcodeScan calls window.merqo.pos.productByBarcode({businessId, barcode}) which returns product + barcodeDetail (unitId, quantityMilli) + stockMilli + unit via ProductRepository.findByBarcodeAll.
- addProductToCart checks isActive, isSellable, stock, calculates unitId from barcodeDetail or saleUnitId or baseUnitId, qtyFromBarcode from barcodeDetail.quantityMilli/1000 else 1, checks existing cart by productId+unitId → quantity +1 (duplicate scan), else new row.
- Conversion: calculateBaseQty uses UnitConversionRepository data, same as SalesService.
- Price: sellingPricePaisa from product, no master modification.
- Stock validation: baseQty vs stockMilli.
- No duplicate SalesService rules in scanner code — scanner only calls product lookup and cart logic, sale creation via SalesService.create.

## 14. Print Failure Handling
Handles:
- printer not found: getPrinterStatus returns offline, messageBn প্রিন্টার পাওয়া যায়নি। সংযোগ পরীক্ষা করুন।
- printer removed: list returns current, status check missing → offline.
- printer offline: mapPrintErrorToBn detects offline → প্রিন্টার অফলাইন। প্রিন্টার চালু করুন।
- invalid printer: sanitized, length check, returns error.
- print API failure: printHtml catches exception, returns Bengali রসিদ প্রিন্ট করা যায়নি। প্রিন্টার পরীক্ষা করে আবার চেষ্টা করুন।
- timeout: not explicitly detectable via Electron print callback, but catch covers.
- malformed print content: escapeHtml prevents injection, no crash.

Critical: printer failure does NOT rollback successful sale — sales and printing separate concerns. If sale succeeds but printing fails, sale remains recorded, stock updated, ledger correct, user informed via printStatus, can retry printing. Never creates second sale.

Implemented in POSScreen handlePrintReceipt: try print, if fails set printStatus with messageBn but sale remains, success modal stays, retry allowed. In SaleDetail handlePrint similar.

Tested via printer.service.test.ts: print failure — sale remains valid, no rollback, sale still exists total_paisa correct.

## 30. Exact Manual Verification Procedure

For Windows 10/11 x64 with real hardware:

1. Prerequisites:
   - Windows 10/11 x64, Node 20+, Git, internet for native rebuild
   - 58mm thermal printer (e.g., Xprinter 58mm) and/or 80mm (Epson TM-T20, Xprinter 80mm) installed via Windows Settings → Printers
   - A4 printer (laser/inkjet) installed
   - USB HID barcode scanner (generic Netum, Inateck) — most send Enter suffix
   - Optional: Bluetooth HID scanner paired as Bluetooth keyboard

2. Build:
   ```
   git clone <repo>
   git checkout arena/01a0aa2b-merqo-retailos
   npm install
   npm run postinstall  # rebuild better-sqlite3 for Electron 30.5.1 ABI 127
   npm run typecheck
   npm run test:unit
   npm run test:db
   npm run build
   npm run dist:win  # generates MERQO-RetailOS-Setup-0.1.0.exe in release/
   ```

3. Clean-machine install:
   - On clean Windows VM without Node/npm, run MERQO-RetailOS-Setup-0.1.0.exe per-user (no admin), verify shortcuts, launch.

4. First-run:
   - Verify DB initializes at %APPDATA%\MERQO RetailOS\merqo.db, logs at logs/, first-run detection.

5. Hardware settings:
   - Open হার্ডওয়্যার সেটিংস, verify printer discovery lists installed printers, count, default.
   - Select 80mm printer, paper width 80mm, save, verify persisted.
   - Select A4 printer, save.
   - Test print 80mm — verify Bengali test page prints with চাল ডাল তেল, no tofu, no clipping.
   - Test print 58mm — switch to 58mm, test print, verify compact.
   - Test A4 invoice — from sale detail, print A4, verify invoice layout.

6. Scanner tests:
   - In hardware settings scanner test area, scan barcode with USB HID scanner — verify detected as scanner (দ্রুত), barcode shown, product lookup if exists.
   - Test suffix Enter (default) — scan should add to cart immediately.
   - Change suffix to Tab in settings, reconfigure scanner to Tab suffix if possible, scan, verify.
   - Change suffix to None, scan, verify timeout-based auto-scan works.
   - Test rapid scans: scan same barcode twice rapidly — verify quantity increments to 2.
   - Test repeated scans after manual qty change: scan once, change qty to 3 manually, scan again → qty 4.
   - Test unknown barcode: scan random barcode not in DB — verify Bengali error এই বারকোডের কোনো পণ্য পাওয়া যায়নি, no fake product created.
   - Test inactive product: create product, deactivate, scan its barcode — verify error সক্রিয় নয়, not added to cart.
   - Test non-sellable: isSellable false → error বিক্রয়যোগ্য নয়.
   - Test Bengali product search: product name চাল, search চাল → found.
   - Test manual entry: type barcode in barcode input, press Enter — should work even if slow typing.

7. POS hardware workflow:
   - Login → POS → focus scanner (F1) → scan barcode → product added → scan same barcode → quantity increments → customer selection → discount if applicable → payment → sale completed.
   - Verify sale exists in sales list, stock deducted exactly once, payment recorded exactly once, customer due correct, audit recorded.

8. Printer workflow:
   - Completed sale → print receipt (80mm) → verify printer request reaches main process (diagnostics lastPrintResult success), verify physical receipt contains business name, invoice number, date/time bn-BD, cashier, customer, product names Bengali wrap, qty, price, totals, paid, due/change, payment methods, footer, no fake data, no placeholder.
   - Verify 58mm receipt: switch to 58mm, print, verify compact readable, no horizontal overflow, totals clear.
   - Verify A4 invoice: print A4, verify dimensions, margins, Bengali font, business info, customer, item table, totals, payment, due.
   - Verify print preview: preview HTML matches final print (same HTML).

9. Print failure handling:
   - Disconnect printer or select invalid printer, attempt print — verify Bengali error প্রিন্টার পাওয়া যায়নি বা প্রিন্টার অফলাইন, sale remains valid, stock/payment/due unchanged, retry works.
   - Test double-click print: rapidly click print twice — verify physically 2 receipts may print if requested but financial data unchanged (sale count same, payment count same).
   - Test failed print followed by retry: fail → retry success → no duplicate.

11. Offline:
    - Disable network, verify scanner, printer discovery, receipt printing, invoice printing, diagnostics all work offline, no internet/cloud.
