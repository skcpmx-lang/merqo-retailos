## 1. Objective
Implement P4.4 Reports & Business Analytics as offline, read-only, integer paisa/milli, parameterized, RBAC-protected, performant reporting layer that reuses existing immutable ledgers (sales, sale_items with line_cost_total_paisa snapshot, purchases, stock_movements, customer_transactions, supplier_transactions, cash/bank/mfs movements, expenses, shifts) to provide sales/purchase/inventory/customer/supplier/finance/expense/profit/shift/dashboard insights with date filtering Today/Yesterday/This week/This month/Previous month/Custom inclusive start 00:00:00.000 end 23:59:59.999, export/print via existing architecture, Bengali-first UI, no demo numbers, charts only actual data.

Goal is not cloud analytics, AI forecasting, ecommerce, multi-store, loyalty, mobile, but **accurate read-only aggregation → immutable cost COGS → running balance → profitability → dashboard** offline.

## 2. Scope
In scope: reports architecture (types, service, queries), sales reports (summary, by product, by category, by cashier, by payment method), purchase reports (summary, by supplier, by product), inventory reports (current stock via stock_levels join products/units/categories + WAC value + status in_stock/low/out_of_stock, low stock filter, movement, valuation), customer reports (due, statement with opening before range + running balance), supplier reports (payable, statement), finance reports (cash, bank, MFS with opening from opening_balance + SUM before range + inflow/outflow categorization + balanceAfter), expense reports (summary, by category, list), profitability P&L (revenue cogs grossProfit expenses netProfit using sale_items snapshot minus return cogs), shift/cash reports, filtering (date presets), export/print if existing architecture supports (CSV export + window.print), UI Bengali-first, tests, performance via indexes aggregation pagination, docs.

Out of scope (V2): cloud analytics, AI forecasting, ecommerce, multi-store, cloud sync, loyalty, mobile, new accounting/inventory architecture, online MFS APIs.

  - getStockValuation: calls getCurrentStock 10000, totalQty SUM, totalValue SUM stockValue, avgWac = totalValue / (totalQty/1000 ||1), counts per status.
  - getStockMovements: stock_movements JOIN products, WHERE business/product/date, ORDER BY sm.created_at DESC, sm.rowid DESC (fixed ambiguous), LIMIT/OFFSET, tries resolve referenceNumber via lookup purchases.purchase_number, sales.sale_number, sale_returns.return_number, purchase_returns.return_number, MOVEMENT_TYPE_LABELS.
  - getCustomerDue: customers LEFT JOIN customer_transactions, GROUP BY customer, MAX lastTxAt, ORDER BY current_due DESC, LIMIT/OFFSET, for each customer gets sales/payments/returns totals via customer_transactions with date filter if range else all, availableCredit = creditLimit - currentDue.
  - getCustomerStatement: customer lookup, rows WHERE customer_id + date range ORDER BY created_at ASC rowid ASC, opening balance = opening_due + SUM before range, running balance = opening + amount per row, totals sales/payments/returns, typeBn map, refNumber lookup sale_number.
  - getSupplierPayable: similar suppliers + supplier_transactions.
  - getSupplierStatement: similar opening before range + running.
  - getCashReport: account lookup, opening = opening_balance + SUM amount before range from cash_movements, movements WHERE account + date range ORDER BY created_at ASC rowid ASC, running balance, categorization: sale, customer_collection/payment, transfer_in, mfs_cash_out as inflows; supplier_payment, expense, transfer_out, mfs_cash_in as outflows; other based on sign; returns inflows/outflows totals + closing.

  - getExpenseSummary: expenses WHERE business + date range, COUNT/SUM for active vs voided vs total.
  - getExpenseByCategory: JOIN expense_categories, GROUP BY category, COUNT/SUM, percentage.
  - getExpenseReport: JOIN expense_categories + cash/bank/mfs accounts for account names, ORDER BY expense_date DESC LIMIT/OFFSET.

## 5. Query Layer & Security
- Parameterized queries only: all WHERE values via `?` placeholders, params array, no dynamic SQL for table names, no string concat for user input.
- No dynamic table/order injection: safeOrderBy allowlist, no user-controlled ORDER BY.
- No path traversal: not applicable for reports (no file paths), but IPC validates businessId etc via Zod.
- READ-ONLY: ReportService never calls INSERT/UPDATE/DELETE, only SELECT, except referenceNumber lookups which are SELECT. Verified via code search no `INSERT|UPDATE|DELETE` in report.service.ts.
- Money integer paisa: all paisa fields SUM COALESCE, integer, no FLOAT, verified via Number.isInteger checks in tests.
- Quantity milli: base_quantity_milli integer, quantityUnits = milli/1000 float for display only, but storage integer.
- RBAC: service layer does not enforce RBAC itself (read-only), but IPC handlers enforce via assertReportPermission checking permissions reports.view/reports.sales/etc or dashboard.view/sales.view/purchases.view/finance.view or isOwner. SessionManager.getCurrentUser() checked, if no session (tests) allowed. No UI-only checks.

## 6. Date Filtering
- getDateRange(preset, customStart, customEnd): today 00:00:00.000 to 23:59:59.999, yesterday same, thisWeek Monday start (day 0 Sun => -6), thisMonth 1st 00:00 to last day 23:59:59.999, prevMonth 1st of prev month to last day of prev month, custom sets hours 00:00 and 23:59:59.999 inclusive. Label en and bn via toLocaleDateString.
- resolveDateRange(filter): if dateRange exists use its start/end, else if fromDate/toDate use those, if only fromDate use fromDate to now.
- Inclusive handling: WHERE column >= ? AND column <= ? with start/end ms inclusive.
- All reports use resolveDateRange for date filtering, ensures inclusive.

## 7. Sales Reports

Excludes cancelled/voided. Uses parameterized.
- By Product: aggregates per product, uses immutable line_cost_total_paisa snapshot for COGS, not today's product cost, grossProfit = netSales - cogs, margin = grossProfit/net*100. Verified via test: purchase at 10000, sale, then update product cost to 20000, report still shows 10000 COGS.

## 14. Profitability (P&L)
- Revenue: grossSales = salesSummary.grossSalesPaisa, discounts = salesSummary.discountPaisa, returns = salesSummary.returnPaisa, netSales = salesSummary.netSalesPaisa - returns (net after returns).
- COGS: SUM sale_items.line_cost_total_paisa WHERE sales not cancelled/voided, minus return cogs SUM sale_return_items.cost_paisa * (base_quantity_milli/1000) WHERE returns not cancelled/voided, using immutable snapshot.
- Gross Profit: netSales - cogs, margin = grossProfit/netSales*100.
- Expenses: operatingExpenses = expenseSummary.activeExpensePaisa, expenseByCategory via getExpenseByCategory.
- Net Profit: grossProfit - operatingExpenses, margin = netProfit/netSales*100.
- Period: dateRange or thisMonth.
- Verified via test: purchase at 10000, sale at 15000, expense 2000 => revenue 15000, cogs 10000, gross 5000, expense 2000, net 3000. Changing product cost after sale does not affect P&L (immutable snapshot).

## 22. Money & Quantity Handling
- Money integer paisa: all paisa fields integer, SUM COALESCE, Math.round for avg, margin, etc, no FLOAT for money storage, only division for display and margin percentage.
- Quantity milli: base_quantity_milli integer, quantityUnits = milli/1000 for display, deficitMilli integer, availableMilli integer.
- No FLOAT for money, verified via Number.isInteger checks in tests.
- WAC: cost_price_paisa integer, stockValue = qtyUnits * wac rounded, averageWac rounded.

## 23. Immutable Cost Snapshot
- Sales reports use sale_items.line_cost_total_paisa which is immutable snapshot of WAC at time of sale, not today's product cost.
- Purchase reports use purchase_items.base_cost_per_unit_paisa and line_total_paisa snapshot.
- P&L uses sale_items snapshot minus return cogs, not current product cost.
- Verified via tests: purchase at 10000, sale, then update product cost to 20000, report still shows 10000 COGS.
